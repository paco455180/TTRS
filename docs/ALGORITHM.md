# 呼吸辨識演算法說明

本文件說明 `js/detect/` 的做法、每個門檻的理由，以及調整時要重跑的測試。

## 1. 臨床背景

- 心臟突然停止後，約 30–40% 的病患在最初幾分鐘會出現 **瀕死呼吸（agonal breathing / gasping）**：零星、費力、像魚離水般的喘氣，常伴隨鼾聲或呻吟，兩次之間有數秒到十幾秒的靜止。
- 旁觀者常把它誤認為「還在呼吸」，導致 CPR 延遲。指引因此規定：**無反應 + 無呼吸或只有喘息 → 視為心跳停止，立刻 CPR**；檢查呼吸 **不超過 10 秒**。
- 所以 app 的任務不是精準測量呼吸率，而是回答一個二元問題：「這是明確的、規律的正常呼吸嗎？」答案不是「是」，就建議 CPR。

## 2. 鏡頭：胸口起伏（`motion.js`）

### 前處理
- 影像縮到 240×320（直式）、灰階。使用者把白色方框（ROI，畫面中央 64%×44%）對準胸口／上腹。
- 每幀在 ROI 內算「列剖面」（每一列的平均亮度），得到一條 1-D 訊號；胸口上下移動時，這條剖面會整體平移。

### 位移估計（`signal.js: profileShift`）
- 目前幀與 **參考幀**（keyframe）的剖面做 SSD 比對，先找整數位移，再在 ±1 px 內以 1/8 px 步進、Catmull-Rom 內插精修，最後拋物線內插。合成測試中誤差 < 0.1 px。
- 參考幀每 2.5 秒、或位移接近搜尋上限、或鏡頭大幅晃動時更新；切換時以最近 5 幀的中位數當基準，避免單幀離群值烙進曲線。
- 逐幀位移超過 40 px/s 視為估計離群值（呼吸動作不可能這麼快），沿用前一值。

### 手震補償
- ROI 上方與下方的背景帶也各算一個位移，平均為「全域位移」gy；胸口的局部位移 **dy = ROI 位移 − gy**。
- 另外把 ROI 分成上下兩半，**exp = 下半位移 − 上半位移**：鏡頭由上往下拍時，胸口靠近鏡頭會讓影像放大（上半往上、下半往下），這個訊號對整體平移天生免疫。
- 兩個訊號都做分析，取峰值振幅較大者。

### 呼吸事件偵測
1. 位移曲線重取樣到 20 Hz，減掉 5 秒移動 **中位數**（比移動平均更不會在稀疏脈衝旁產生副瓣）。
2. 找峰值：相鄰峰至少 0.9 秒（≤ 66 次/分）；突出度 ≥ max(5 × 雜訊, 0.35 px + 手震抖動量)。雜訊用原始逐幀差分的 MAD/√2 估計。相對於最大峰 < 25% 的小峰捨棄。
3. 輸出：次數、每分鐘次數（有 ≥2 個間隔時用平均間隔）、規律性（1 − 間隔變異係數）、振幅變異、最長無呼吸間隔、**活動比例**（|訊號| 超過峰高 30% 的時間比例：正弦式的正常呼吸約 0.8，短促喘息＋長時間平坦約 0.1–0.3）。
4. 品質分數 = fps × 晃動比例 × ROI 對比 × 亮度 的乘積；< 0.35 → 無法判斷。

## 3. 麥克風：喘息聲（`audio.js`）
- 每 ~40 ms 算 RMS；雜訊底以「往下快、往上慢」追蹤。
- 爆發：RMS > 4× 雜訊底且持續 80–2000 ms；兩次爆發間隔 ≥ 1.5 秒。2–8 次符合 → `gaspLike`。
- 密集爆發（說話、交通）→ 標記 `noisy`，判讀時略過。
- 這是刻意保守的啟發式，只當作輔助證據；正式版由訓練後的聲音模型取代。

## 4. 判讀融合（`fusion.js`）

| 條件 | 結果 |
| --- | --- |
| 觀察 < 8 秒 | 無法判斷（未完成） |
| 品質 < 0.35 | 無法判斷 → 建議 CPR |
| ≥ 3 次、8–40 次/分、規律 ≥ 0.55、振幅變異 ≤ 0.9、最長間隔 ≤ 7.5 秒、活動比例 ≥ 0.45 | **規律呼吸** |
| 恰好 2 次、型態像正常且觀察 < 14 秒 | 要求再觀察 5 秒（`extend`） |
| 恰好 2 次、型態像正常且已觀察 ≥ 14 秒 | 規律呼吸（信心較低） |
| 0 次 | 沒有呼吸 → CPR |
| 1 次且不是短促脈衝（活動比例 ≥ 0.35 或 snr < 6） | 沒有呼吸（多半是殘留手震）→ CPR |
| 其他（稀疏、不規則、短促） | 疑似瀕死呼吸 → CPR |

- 聲音 `gaspLike`：把「沒有呼吸／無法判斷」提升為「疑似瀕死呼吸」；若影像說正常，只降低信心並提示再確認。
- AI 模型（信心 ≥ 0.7）：只能把「正常」改成需要 CPR 的類別，或在無法判斷時給答案；**永遠不能把「沒有呼吸／瀕死呼吸」改成「正常」**。

門檻集中在 `DEFAULT_THRESHOLDS`，調整後執行 `npm test`。

## 5. 已知失敗模式與對策

| 情境 | 現象 | 對策 |
| --- | --- | --- |
| 厚外套、被子 | 看不到起伏 → 沒有呼吸 | 指引使用者露出胸口／上腹；結果仍建議 CPR（安全方向） |
| 病患被搖晃、旁人壓胸中 | 大幅動作 → 品質低 | 提示「檢查時暫停搖晃」；無法判斷仍建議 CPR |
| 施救者手抖 | 假位移 | 背景補償 + 抖動自適應門檻；提示靠在膝蓋或地面 |
| 極暗 | 亮度 < 15 → 無法判斷 | 提示開手電筒（下一版可自動開閃光燈 torch） |
| 呼吸很慢但規律 | 10 秒只有 2 次 | 延長到 15 秒 |
| 瀕死呼吸剛好很規律（少見） | 可能誤判為正常 | 活動比例門檻（短促脈衝 → 不算正常）；聲音輔助；AI 模型 |
| 嬰兒／幼童 | 胸口小、頻率高 | 尚未針對兒童調參（見 ROADMAP） |

## 6. 驗證方式
- `tests/detect.test.mjs`：合成影像（帶紋理背景 + ROI 內次像素位移 + 手震 + 感測雜訊）跑完整流程。
- `tests/e2e.mjs`：Chromium 假鏡頭播放合成 Y4M 影片，走完 UI 流程，檢查結果與畫面。
- 真人驗證計畫見 `docs/ROADMAP.md`（CPR 假人、志願者正常呼吸／憋氣、急診端錄影回溯）。
